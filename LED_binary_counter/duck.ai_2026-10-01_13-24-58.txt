All of these diagnostics have the same underlying cause: **VS Code’s C/C++ IntelliSense does not know which Arduino board core should be used to parse your `.ino` file**.

`Serial`, `pinMode()`, `digitalWrite()`, `delay()`, `HIGH`, `LOW`, and `OUTPUT` are not built-in C++ symbols. They come from the Arduino board core, primarily through `Arduino.h`. Arduino IDE 1.8.19 automatically supplies the Arduino include paths and performs Arduino-specific preprocessing before compiling. The VS Code C/C++ extension, however, analyzes the file independently using its own configuration.

That is why your sketch can compile or upload successfully while VS Code still displays errors.

The fact that VS Code shows a Serial Monitor button only means that the Arduino extension detected the serial tooling. It does **not** prove that IntelliSense has loaded the selected board’s core headers.

The tutorial’s command-line build also explicitly supplies a board using an FQBN such as `arduino:avr:uno`; that tells Arduino CLI how to compile the sketch, but it does not automatically configure the separate C/C++ IntelliSense engine. [1][2]

- `Serial` — declared by the Arduino core’s serial-related headers.
- `pinMode()` and `digitalWrite()` — Arduino core functions.
- `delay()` — Arduino timing function.
- `OUTPUT`, `HIGH`, and `LOW` — Arduino core constants/macros.
